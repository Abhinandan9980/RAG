Working spec for the full UI/UX revamp of this repo's frontend (`frontend/`). Product truth lives in `PRODUCT.md`; this file is the build plan and decision record so the phased work survives across sessions. Update it as phases complete or decisions change — do not let it drift from reality.

## Governing design principles (apply to every phase from here on)

- **Minimize clicks, always.** Every flow gets audited for "does this need to be a separate click/page/dialog." Default to inline, progressive-disclosure, and single-screen patterns over multi-step modals or buried settings, especially in SQL, Career, and Analyst studios where the current implementation already has excess steps (native selects, separate review-then-execute stages, drawer-hidden history).
- **Design for a public, screenshot-shareable audience, not just recruiters.** The audience for this includes LinkedIn/Instagram-style public sharing, not only a recruiter clicking a portfolio link — screens should be visually striking and "amaze" on their own out of context (a single screenshot should read as impressive), not just be functionally clean. This raises the bar beyond "usable and tidy" to "worth posting."

## Committed landing direction: "The Surveyor's Instrument"

Chosen via Impeccable's mandatory direction-seed roll (assigned index 5 of 7 grounded candidates authored for this brief), weighed against dealt catalog challengers (strongest: an oscilloscope/signal-bench world, which loses on brand-register fit; the rest — a decorable pastel room, a LEGO instruction booklet, bioluminescent plankton, a fashion mook spread — fail outright on tone for a rigor-signaling recruiter audience).

- **World:** Land-surveying instrumentation — the discipline that establishes objective, measured ground truth before anything gets built. Theodolites, sight lines, triangulation, contour maps, benchmark markers, compass roses, brass instrument tones, engraved measurement marks.
- **Color strategy:** Committed (one saturated accent). Deep surveyor's-ink navy field, brass/bronze secondary, warm ivory/contour-paper content tone, one signal-orange crosshair accent reserved for "live"/confidence moments.
- **Type:** A precise geometric sans for labels/data (Space Grotesk already fits) paired with a monospace for coordinates/readouts (IBM Plex Mono already fits). Fate of the existing Newsreader editorial serif is an open decision for the tokens pass.
- **Hero mechanism:** A crosshair/reticle sweeps a field of scattered, hazy data shapes (documents, database tables, resumes, spreadsheets). It locks onto enough points, triangulation lines snap taut, and they resolve into one confidence-scored, cited answer — a benchmark being set. Build as a Three.js topographic terrain scene (satisfies both the direction and the original ambition for a real 3D showpiece, without reverting to generic aperture/particle glassmorphism).
- **System mapping:** The four studios = four instruments sighting the same terrain of truth. Scroll = walking a survey traverse; section dividers are elevation/contour lines, not generic fades. "No guessing" is literal: a surveyed point is fixed and citable, an eyeballed guess is not.
- **Mode discipline:** This full intensity applies to the public landing/marketing surface only. App screens inherit the same token vocabulary (navy/brass/ivory/orange, same type pairing) in a Restrained strategy — neutrals plus the one accent, no crosshair/triangulation theatrics — per Operate-mode rules.
- Direction contract (THESIS/OWN-WORLD/STORY/FIRST VIEWPORT/FORM/FINISH) gets written as an HTML comment in the root layout when the landing rebuild starts, per Impeccable's process, and DESIGN.md gets written from the shipped result at finish — not before.

5. **Chat studio rebuild (done)** — replaced the blank-flash mount state with a real skeleton; replaced the hover-only (touch-inaccessible, non-keyboard-focusable) token-usage tooltip with a `Popover`; tightened composer icon buttons responsively and hid the least-essential one (prompt library) on narrow screens to give the textarea more room; redesigned the message metadata row so confidence is the prominent trust signal (colored by tier, shield icon), mode is quiet secondary text, and reasoning/sources read as clearly-secondary ghost toggle buttons instead of four same-weight pills. **Also found and fixed two compounding real bugs, caught only by testing against the live backend (user-reported: "actual ask one is scrolled down")**:
1. `MessageList.tsx`'s auto-scroll used `scrollIntoView()`, which nudges *every* scrollable ancestor (including the window) to bring the target into view — adding `block: "nearest"` was not sufficient by itself, since the window still has some scrollable overflow. Fixed by scrolling the actual Radix `[data-radix-scroll-area-viewport]` element directly via `scrollTo()`, never touching the window.
2. The deeper cause the first fix exposed: `app/chat/page.tsx`'s message-area height was a hand-guessed `calc(100svh-13rem)`/`calc(100svh-15.5rem)`, which measurement proved was wrong by **116px on desktop and 275px on mobile** (mobile was bad enough that the composer rendered partly *behind* the bottom tab bar). Focusing the composer triggered the browser's native "scroll focused element into view," which is what the user actually saw. Fixed by measuring real available height in JS (`getBoundingClientRect()` minus the mobile nav's real height, updated on resize via `ResizeObserver`) instead of guessing a constant, plus `overflow-hidden` on the outer canvas as a safety net (the same pattern already proven in `aurasql/query/page.tsx`). Verified: `window.scrollY` stays `0` through focus → type → send → stream → final response, on both 1280px and 390px viewports, confirmed via screenshots.
